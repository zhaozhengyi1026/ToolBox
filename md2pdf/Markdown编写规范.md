# Markdown 编写规范

本规范适用于本项目的 Markdown → Pandoc HTML → Chrome/Edge PDF 流程。目标是减少不同 Markdown 解析器之间的语法歧义，保证目录、图片、表格和分页结果稳定。

脚本使用 Pandoc 的 `markdown` 输入格式。只要使用本规范列出的写法，并在交付前通过 `--strict` 检查，就可以保证脚本对本文所覆盖的标题、正文、引用、列表、表格、图片、代码块、分隔线和分页标记进行稳定解析。不要混用其他编辑器特有但 Pandoc 不一定支持的扩展语法。

## 开始编写前：必须遵守的规则

以下规则是本项目 Markdown 的最低要求：

1. 文件保存为 UTF-8，扩展名使用 `.md`。
2. 标题只使用 `# 标题`、`## 标题`、`### 标题` 这种写法，`#` 后必须有空格。
3. 标题、正文、引用、列表、表格、图片、代码块、分隔线和 HTML 分页标记之间必须留一个空行。
4. 分隔线 `---` 必须单独成行，并且前后各有一个空行。
5. 不使用“标题文字下一行写 `---` 或 `===`”的 Setext 标题写法。
6. 引用写成 `> 内容`，引用结束后必须留一个空行。
7. 围栏代码块必须成对出现，开始和结束都使用三个反引号。
8. 本地图片使用相对于当前 Markdown 文件的路径，并确保图片真实存在。
9. 表格必须包含表头和表头分隔行，表格前后必须留一个空行。
10. 正式转换前必须执行带 `--strict` 的命令，并先查看生成的 HTML，再确认 PDF。

最小合规示例：

````markdown
# 文档标题

## 一、章节标题

这是一段正文。

> 这是一条提示。

### 步骤一：准备数据

- 第一项
- 第二项

| 字段 | 说明 |
|---|---|
| name | 名称 |

![图片说明](images/example.png)

---

## 二、下一章节

```python
print("代码块必须闭合")
```
````

## 一、文件与编码

- 文件扩展名使用 `.md`。
- 文件统一保存为 UTF-8，推荐 UTF-8 without BOM 或 UTF-8 with BOM。
- 图片和附件尽量与 Markdown 放在同一项目目录内。
- 文件名可以使用中文，但不要使用 `*`、`?`、`<`、`>` 等 Windows 不允许的字符。

## 二、段落和空行

标题、正文、引用、列表、表格、图片、代码块和分隔线属于不同内容块。不同内容块之间应留一个空行。

推荐：

```markdown
这是一段正文。

> 这是一段引用。

---

这是分隔线后的正文。
```

不要写成：

```markdown
> 这是一段引用。
---
```

后一种写法存在语法歧义。Pandoc 可能将 `---` 当成 Setext 标题下划线，使引用内容变成二级标题并进入目录。

## 三、标题

标题统一使用 ATX 写法，即行首的 `#`，并在 `#` 后保留一个空格。

```markdown
# 文档标题

## 一级章节

### 操作步骤

#### 补充说明
```

不要使用以下写法：

```markdown
##标题后缺少空格

容易产生歧义的标题
---
```

建议每份文档只有一个 `#` 一级标题。正文层级依次使用 `##`、`###`、`####`，不要从 `##` 直接跳到 `####`。

启用目录时，脚本默认收集一级至三级标题。不要为了加粗一句话而使用标题语法，否则该文字也会进入目录。

## 四、分隔线

分隔线使用单独一行的三个连字符，并在前后各留一个空行：

```markdown
上一部分内容。

---

下一部分内容。
```

不要让 `---` 紧贴普通文本、引用、表格或图片。

## 五、引用

引用标记 `>` 后保留一个空格。多段引用时，每段都应带 `>`，或使用只包含 `>` 的空引用行分隔。

```markdown
> 这是第一段引用。
>
> 这是第二段引用。
```

引用结束后留一个空行，再开始其他内容块。

## 六、列表

无序列表统一使用 `-`，标记后保留一个空格：

```markdown
- 第一项
- 第二项
  - 子项目
```

有序列表写法：

```markdown
1. 第一步
2. 第二步
3. 第三步
```

列表前后留一个空行。子项目使用两个或四个空格缩进，并在同一份文档中保持一致。

## 七、表格

表格前后留一个空行，表头下必须有分隔行：

```markdown
| 方案 | 成本 | 时效 |
|---|---:|---:|
| A | 1000 | 300 |
| B | 900 | 280 |
```

- `---` 表示默认对齐。
- `---:` 表示右对齐。
- `:---:` 表示居中。
- 单元格内容中如需显示竖线，写成 `\|`。
- 不建议在表格单元格内放置很长的代码块或复杂 HTML。

## 八、图片

推荐使用相对于 Markdown 文件的路径：

```markdown
![全国仓库网络图](images/network.png)
```

注意事项：

- 必须填写有意义的图片说明，不要只写 `![](...)`。
- 确认文件名、扩展名和大小写完全一致。
- 路径中有空格时，使用尖括号包裹：`![说明](<images/network map.png>)`。
- 不要引用仅存在于个人临时目录中的绝对路径。
- 当前转换脚本会把本地图片嵌入 HTML，生成的单个 HTML 可以独立查看。

## 九、代码和公式

行内代码使用一对反引号：

```markdown
执行 `python md_to_html.py` 开始转换。
```

多行代码使用成对的三个反引号，并注明语言：

````markdown
```python
print("Hello")
```
````

代码块必须有结束标记。代码块前后各留一个空行。

## 十、目录与分页

目录只在命令中加入 `--toc` 时生成：

```powershell
python md_to_html.py "." --toc --pdf
```

不需要目录时省略 `--toc`：

```powershell
python md_to_html.py "." --pdf
```

如需强制另起一页，可以在 Markdown 中单独插入：

```html
<div class="page-break"></div>
```

分页标记前后留一个空行。

## 十一、转换前自动检查

脚本会在每个文件转换前自动检查以下问题：

- 标题的 `#` 后缺少空格；
- 分隔线前后缺少空行，存在标题解析歧义；
- 围栏代码块缺少结束标记；
- Markdown 中引用的本地图片不存在。

普通模式下，脚本显示文件名、行号和警告后继续转换：

```powershell
python md_to_html.py "." --pdf
```

正式批量交付前建议启用严格模式。只要发现格式问题，该文件就不会转换，脚本最终返回失败状态：

```powershell
python md_to_html.py "." --toc --pdf --strict
```

### 严格模式能检查的内容

- `#` 标题后是否缺少空格；
- 分隔线或 Setext 标记前后是否缺少空行；
- 围栏代码块是否缺少结束标记；
- Markdown 直接引用的本地图片是否存在。

### 仍需人工确认的内容

严格模式只能发现确定性较高的格式问题，不能判断文档内容是否符合作者本意。以下项目必须通过 HTML 预览确认：

- 标题级别和目录层级是否符合业务逻辑；
- 表格中的行列、合并需求和数据内容是否正确；
- 图片本身是否清晰、方向是否正确；
- 超长表格或图片在 A4 页面上的分页是否合适；
- 原生 HTML、数学公式或第三方 Markdown 扩展是否得到预期渲染；
- 网络图片或外部链接在转换时是否可以访问。

不要仅以“严格模式没有警告”代替 HTML 预览。推荐的交付流程是：

1. 使用 `--strict` 生成 HTML 和 PDF。
2. 打开 HTML，检查目录、标题层级、表格和图片。
3. 打开 PDF，检查分页、页边距和字体。
4. 确认无误后再交付文件。

## 十二、推荐文档模板

````markdown
# 文档标题

简要说明文档目的、适用对象和主要内容。

## 一、背景

背景正文。

## 二、方案

### 步骤一：准备数据

操作说明。

![数据示意图](images/example.png)

### 步骤二：执行计算

1. 完成第一项操作。
2. 完成第二项操作。

> 注意：这里填写重要提示。

---

## 三、结论

结论正文。
````

提交或批量转换前，建议使用 `--strict` 完成一次全目录检查。
